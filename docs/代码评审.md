## 3. 详细问题清单

### P0-01 后端全量测试无法收集

- 优先级：P0
- 模块：Backend Tests
- 文件：`backend/tests/test_save_service.py`
- 证据：第 63 行 `for summary in summaries:` 后没有缩进代码块，文件在第 64 行结束。
- 影响：`pytest backend/tests` 直接中断，后端整体质量闸门失效。
- 建议：补全测试，至少断言 `SaveSummary` 不包含 `state`，并新增 update/delete/invalid save_id 覆盖。

### P0-02 配置接口路径安全判断方向错误

- 优先级：P0
- 模块：Backend Config API
- 文件：`backend/app/api/config.py`
- 位置：`resolve_config_path()`
- 当前代码：

```python
if not DATA_PATH.is_relative_to(config_path):
    raise HTTPException(status_code=403, detail="Access denied: Path traversal detected")
```

- 问题：判断方向反了。应判断 `config_path` 是否位于 `DATA_PATH` 内。
- 影响：合法文件会被错误拒绝为 403。
- 建议：

```python
resolved_data_path = DATA_PATH.resolve()
config_path = (resolved_data_path / config_name).resolve()
if not config_path.is_relative_to(resolved_data_path):
    raise HTTPException(status_code=403, detail="Access denied: Path traversal detected")
```

### P0-03 存档 API 契约已写但路由未实现/未注册

- 优先级：P0
- 模块：Backend Saves API
- 文件：`docs/api_contract.md`、`backend/app/main.py`
- 缺失文件：`backend/app/api/saves.py`
- 证据：文档定义 `GET/POST/PUT/DELETE /api/saves`，但 `main.py` 只注册 health/game/config。
- 影响：Phase 7 核心接口不可调用。
- 建议：新增 saves router，注册到 `main.py`，补 `backend/tests/test_save_api.py`。

### P0-04 `update_save()` 不落盘

- 优先级：P0
- 模块：Backend Save Service
- 文件：`backend/app/services/save_service.py`
- 位置：`update_save()`
- 问题：构造新 `SaveRecord` 后直接 `return record`，没有 `_write_save(record)`。
- 影响：更新接口即使返回成功，文件仍是旧数据。
- 建议：返回前写盘，并测试重新读取后的内容。

### P0-05 `save_id` 生成后缀为空

- 优先级：P0
- 模块：Backend Save Service
- 文件：`backend/app/services/save_service.py`
- 当前代码：

```python
suffix = uuid4().hex[:0]
return f"save_{timestamp}_{suffix}"
```

- 问题：`[:0]` 永远返回空字符串。
- 影响：同一秒创建多个存档会生成同一个 ID，导致覆盖。
- 建议：改为 `uuid4().hex[:8]` 或更长，并增加冲突重试。

### P1-01 存档错误类型未被 API 层映射

- 优先级：P1
- 模块：Backend Save Service/API
- 文件：`backend/app/services/save_service.py`
- 问题：`InvalidSaveIdError`、`SaveNotFoundError`、`SaveIOError` 只定义在 service 层，没有 API 层转换为文档规定响应。
- 影响：接入路由后容易返回非契约 500。
- 建议：saves router 统一捕获并返回 `GameError` 或专用 Save response。

### P1-02 创建/更新存档没有校验协议版本

- 优先级：P1
- 模块：Backend Save Service
- 文件：`backend/app/schemas/save.py`、`backend/app/services/save_service.py`
- 问题：`contract_version` 若未校验会被误当作存档格式版本落盘。
- 影响：违反 Phase 7 固定 `contract_version=1` 与 `save_format_version=1` 的契约。
- 建议：API 层或 Pydantic schema 校验 `contract_version == 1`，否则返回 `UNSUPPORTED_VERSION`；存档落盘使用服务端 `save_format_version`。

### P1-03 Config API 测试路径不一致

- 优先级：P1
- 模块：Backend Tests
- 文件：`backend/tests/test_config_api.py`
- 问题：同时使用 `api/config/...`、`/api/config/...`、`/ghost_config.json`。
- 影响：测试不能准确验证 config router。
- 建议：统一使用 `/api/config/{config_name}`；不存在配置测试应请求 `/api/config/ghost_config.json`。

### P1-04 Config API 未限制文件名/扩展名/配置白名单

- 优先级：P1
- 模块：Backend Config API
- 文件：`backend/app/api/config.py`
- 问题：只要在 `data/` 下的文件理论上都可被读取。
- 影响：可能暴露非公开临时文件。
- 建议：白名单限制 `race.json`、`job.json`、`skill.json`、`effect.json`、`buff.json`、`config.json`，或至少使用严格 JSON 文件名正则。

### P1-05 `core_service.py` 在导入时固化 `USE_MOCK_CORE`

- 优先级：P1
- 模块：Backend Core Service
- 文件：`backend/app/services/core_service.py`
- 问题：环境变量只在模块导入时读取一次。
- 影响：测试或运行时修改环境变量不会生效，容易误判 mock/real core 模式。
- 建议：封装 `is_mock_core_enabled()`，每次请求时读取。

### P1-06 C++ Core 异常没有包装为契约错误

- 优先级：P1
- 模块：Backend C++ Bridge
- 文件：`backend/app/services/cpp_core_client.py`、`backend/app/services/core_service.py`
- 问题：可执行文件不存在、超时、非零退出、stdout 非 JSON 会直接抛异常。
- 影响：HTTP 可能返回 500，而不是 `CPP_CORE_ERROR`。
- 建议：捕获异常，返回统一 `GameActionResponse(ok=false, error.code="CPP_CORE_ERROR")`。

### P1-07 C++ 默认路径仍指向 `build-ninja`

- 优先级：P1
- 模块：Backend/C++ Integration
- 文件：`backend/app/services/cpp_core_client.py`、`backend/README.md`、`scripts/verify_abel_core_cli.py`、`scripts/start_phase6_dev.ps1`

### P1-08 C++ 事件 message 硬编码
